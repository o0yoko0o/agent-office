# External Integrations

**Analysis Date:** 2026-10-28

## APIs & External Services

**Agent transcript sources:**
- Claude Code, Codex, Command Code, Cursor, Droid, Gemini CLI, opencode and Qwen Code
  - Integration method: local filesystem discovery and tailing in `src/ingest/`
  - Auth: each agent's existing local login/configuration

**Remote execution APIs:**
- Vercel Sandbox, Daytona, Railway, boat and SSH
  - Integration method: platform adapters under `src/remote/` and `src/control/cloud/`
  - Auth: platform login files/CLIs or environment tokens; values are not documented here
  - Remote shell contract: small POSIX shell commands, transcript reads and process control

**MCP:**
- The office exposes MCP-facing behavior under `src/mcp/`
  - Integration method: local MCP server/client modules and office state files

## Data Storage

**Databases:**
- None detected; the application is file- and process-oriented

**File Storage:**
- Local agent transcripts and configuration files
- `~/.agentoffice/` stores office state, keys, links, remotes and runtime files
- Remote hosts retain agent files and platform-specific session/scrollback data

**Caching:**
- No general-purpose cache service detected
- HTTP static assets use hashed/immutable behavior in `src/server/static.ts`

## Authentication & Identity

**Auth Provider:**
- Local control authentication implemented in `src/control/auth.ts`
  - Token storage: one-time unlock link, cookie and browser-held page token
  - Session management: local office secret and rotating unlock state

**OAuth Integrations:**
- None implemented in this repository; platform CLIs may provide their own login flows

## Monitoring & Observability

**Logs:**
- Process/service logging through Node streams and service helpers in `src/control/service.ts`
- Office state is streamed to browsers over Server-Sent Events

## CI/CD & Deployment

**Hosting:**
- npm package distribution; site build is generated by `scripts/build-site.mjs`

**Docker (fork only):**
- `make up` runs the office from `compose.yaml` on `127.0.0.1:4848`. Agent transcript folders (`~/.claude/projects`, `~/.claude/sessions`, `~/.codex/sessions`, `~/.local/share/opencode`, `~/.gemini/tmp` and the others from `src/ingest/discover.ts`) are bind-mounted read-only at the same path, and only when they exist (`scripts/docker/mounts.sh`).
- The container uses `AGENT_OFFICE_HOME=/var/lib/agentoffice`, so its `office.json` never replaces the host's. The host's `~/.agentoffice/outbox` is mounted read-only at `/var/lib/agentoffice/outbox`, so MCP signals arrive. `office_peers` can't reach the container office, because the MCP server only finds offices through the host's `office.json`.
- opencode's SQLite database (WAL) opens read-only through the mount (checked on Docker Desktop for macOS).

**CI Pipeline:**
- GitHub Actions workflows in `.github/workflows/ci.yml`, `release.yml`, `site.yml` and `windows.yml`

## Environment Configuration

**Development:**
- Runtime configuration comes from CLI flags, `~/.agentoffice/` files and optional platform CLI logins.
- Platform credentials remain in local login/configuration stores or environment variables; values are not documented here.

**Production:**
- The npm package runs on Node.js 18 or newer and uses the same local configuration model.
- Remote targets add provider-specific CLI/API credentials and runtime prerequisites.

## Webhooks & Callbacks

**Incoming:**
- Local hook routes are handled under `/api/hook/**` by `src/control/` when control is enabled

**Outgoing:**
- Remote adapters issue platform API/CLI operations for sandbox lifecycle and agent execution
